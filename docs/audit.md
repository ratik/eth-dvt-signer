# Adversarial audit of the signing path

Scope: authorization safety, durable recovery, crash consistency, concurrency, partial-signature
collection, Byzantine participants, timeouts and limits, and the process lifecycle.

Method: read the code paths below, then reproduce every claim with a test. Tests use a
deterministic simulation where possible and real processes otherwise. Passing tests are evidence,
not a proof.

## 1. Trust boundaries

| Event | Where | Code |
| ----- | ----- | ---- |
| Authorization visible (in memory) | The executor, inside `Store::apply_block`, which holds `&mut` until `sync`. | `src/storage.rs` |
| Authorization durable | When `Metadata::sync` returns. | `src/storage.rs` |
| Signer learns an authorization | `Committed` values, sent after the sync and before any client answer. At start, read from disk. | `src/executor.rs`, `src/dkg/actor.rs` |
| Duty decided, signing root computed | `Protection::authorize` inside `Store::apply_block`, from the typed duty of the finalized command. The record and the authorization go into the block's one sync. | `src/slashing.rs`, `src/storage.rs` |
| Signer learns a duty authorization | `(ceremony round, root)`, sent after the sync and before any client answer (`AuthorizedDuties`). At start, `Protection::authorized_duties` read from disk. | `src/executor.rs`, `src/engine.rs`, `src/dkg/actor.rs` |
| Partial signature generated | Only in `dkg::actor::partial`: for the local coordinator, for a peer request, or for a parked request that `Authorized` releases. | `src/dkg/actor.rs` |
| Signature returned | The coordinator's `sign` or `sign_duty`, after recovery and verification. | `src/signer/coordinator.rs` |
| State restored from disk | `Store::init` (state), `Secrets::init` (shares), marshal (re-delivery from its processed height), the simplex journal. | |
| Messages served before catch-up | HTTP and p2p are up at once. Signing requests are refused (`not_authorized`) or parked. | `src/rpc.rs`, `src/dkg/actor.rs` |
| Coordinator retries | The coordinator re-sends requests to silent participants every 500 ms until the deadline. Clients may repeat requests. | `src/signer/coordinator.rs` |
| Allocations | In-flight counter (at most 256, drop guard). Response sessions (drop guard). Parked queue (256 in total, 64 per peer, 16 blocks). | `src/signer/coordinator.rs`, `src/dkg/parked.rs` |

## 2. Findings

| ID | Severity | Finding | Reproducer | Status |
| -- | -------- | ------- | ---------- | ------ |
| BUG-1 | High: Byzantine liveness | The coordinator's give-up check counted a participant twice when it sent a final refusal **and** three invalid partials. One Byzantine node could make signing fail (`INSUFFICIENT_SIGNERS`) while three honest signers were available. | `tests/signing.rs::one_byzantine_participant_cannot_abort_signing` (deterministic) | Fixed: the check counts distinct participants, with saturating arithmetic. |
| BUG-2 | Critical: replicated-state divergence | The executor skipped heights it had already applied, but never checked that a delivered block was the next one. The state partition can be behind marshal's processed height: its newest copy torn or damaged after the block was acknowledged, or the partition deleted or restored alone. The node then skipped finalized blocks silently. Observed: block 8 was `Accepted` on node 0 and `UnknownCeremony` on the damaged node 3. A skipped authorization lets that node accept a conflicting payload locally. | `tests/e2e/lifecycle.rs::f4_corrupted_state_fails_closed` (the hold hook pins the damage after the acknowledgement), `f4_lost_state_fails_closed` | Fixed: the executor refuses a height that is not the next one, and the node stops. A copy torn *before* the acknowledgement is legitimately re-delivered and repaired: `f4_torn_unacknowledged_write_is_replayed`. |
| BUG-3 | Medium: operability | A node that stopped on a fatal error (for example the check above) exited with status 0. A supervisor could not see the failure. | `f4_lost_state_fails_closed` | Fixed: a node that stops on an error exits with status 1. The other exit statuses are planned stops: 75 (its consensus epoch ended), 76 (its epoch was closed with `--close-epoch-at`), 77 (the anchor shows a rollback). |
| BUG-4 | Medium: availability under concurrency | Identical concurrent requests on one node each ran a full task: their own command, their own requests to every participant, and every participant's answers fanned out to every session (N sessions, about 3N² messages through 64-slot buffers). On a loaded machine, 256 identical requests produced 43 signatures, then 1. The rest timed out. | `concurrency::e3_in_flight_limit` (first version), in full-suite runs | Fixed: identical requests in flight on a node share one task and its result (at most 1024 waiters, then `503`). With 120 identical requests, the slowest took 1.1 s before and 0.26 s after. |
| BUG-5 | Low: reporting | A validator duty was retried through a coordinator that had not applied the original block yet. That coordinator submitted the duty again, consensus decided it `AlreadyAccepted` in a later block, and the coordinator reported that later block as the authorization's height. The signature and the slashing record did not change, but the reported identity of the authorization was not the original one. Other seeds of the duty simulations found it. | `SIM_SEED=9` and `16` of `tests/eth_duties.rs::authorization_outlives_its_coordinator`. That test now also covers it deterministically. | Fixed: the duty receipt carries the height of the block that authorized the root (`authorized_at`). |
| BUG-6 | High: revocation bypass | `--revoked-client-certs` named a certificate by the SHA-256 of its DER (docs/tee.md). ECDSA accepts `(r, s)` and `(r, n - s)` alike, and neither webpki nor aws-lc prefers one, so the holder of a revoked certificate could re-encode its signature: the certificate still verified under the operator's CA, its DER was another one, and the handshake check, the check on open connections and a revoked CA of `--client-ca` all admitted it again. This is the case revocation exists for: a stolen operator certificate, whose holder has its key. | `tls::tests::a_revoked_certificate_is_refused_however_its_signature_is_encoded` (P-256 and P-384; it reaches the API with the re-encoded certificate before the fix) | Fixed: the list is matched against every form a certificate can take (`tls::fingerprints`), so a line `openssl` printed from either form refuses both. The list's own format is unchanged. |
| BUG-7 | High: liveness under `f = 1` | The gateway returned any status but 200 and 502-504 as the node gave it ("refusals are final"), without asking another node, and `answered()` cleared that node's failure. One faulty node first in `--nodes` order could answer 412, 404, 400 or 500 to every request and make the validator miss every duty, although gateway.md claimed a faulty coordinator within `f = 1` could not. A refusal is one node's word; consensus decides a duty once, so an honest network refuses it on every node. | `gateway::tests::one_node_refusing_everything_cannot_lose_a_duty` (the replaced test asserted the old behaviour: status 412 after one attempt) | Fixed: a refusal needs `route::REFUSAL_AGREEMENT` (2) nodes to give the same status; a node the others contradict is marked faulty for 60 s; with none agreed, the last refusal is returned. A genuine refusal costs one extra request. |
| BUG-8 | High: the anchor disabled by one node | A node's own prefix in the anchor is its own to write. `AnchorStore::latest_sequence` doubled its probe with `saturating_mul`, so a record at `u64::MAX` (about 65 objects to write, and WORM keeps them) left it asking for that one place for ever. `read_anchor` read the nodes one after another and skipped only `Malformed` errors, so one node's hang or error failed the whole read: every honest node then timed out and started degraded, with no anchored marks, no gate and no rollback detection (exit 77), under the restart floor alone. That is the whole of L-1's mitigation, removed by one faulty writer. | `anchor::tests::the_search_for_the_latest_record_ends_on_a_record_at_the_last_place` (without the fix the test does not end: cargo reports it running after 60 s, one core spinning) | Fixed: the probe ends at `u64::MAX`, and the nodes are read at once, each with its own deadline (`ANCHOR_NODE_TIMEOUT`, 10 s), a node left out whatever went wrong with it. |
| BUG-9 | Medium: one node makes an honest coordinator return another duty's signature | The executor hands a duty's receipt to the waiter of its transaction id, which the submitter chooses at random and gossips with the transaction; nothing checks that ids are unique, or that a transaction is the one its waiter submitted. A faulty leader that saw `{id: X, duty D}` could propose a block with `{id: X, duty D_old}`, an already authorized duty of the same validator (`AlreadyAccepted`), and leave D out. The honest coordinator then collected partials for `D_old`'s root, which verify, and returned that signature as D's: the validator client published a signature that does not verify for its duty and missed it. Slashing protection held (only authorized roots were signed). The gateway's own signature check caught it; a node's own Web3Signer API did not. | `signer::coordinator::tests::an_authorization_of_another_duty_is_never_signed` (without the check the coordinator goes on to collect partials for the other root) | Mitigated: the coordinator compares the receipt's signing root with the one it computes from the typed duty and refuses a mismatch (`503`, `WrongAuthorization`): a retry, here or on another node, gets its own authorization. Not done: keying waiters by the transaction's digest rather than its id, which would also cover the commands without a root to compare (`ActivateGeneration`, `AbortResharing`, `StartCeremony`, the development `Sign`). |
| BUG-10 | High: one node delays every duty | Every transaction a peer gossiped went into the mempool; only builder registrations had a bound. A faulty node could gossip about 1000 near-32 KiB duties a second (the channel's quota) for unknown validators at the current slot: they pass the horizon, a block holds about 16, and the leader takes the oldest first. Honest duties waited behind them on every node, and every node's queue grew by about 30 MB/s. | `application::tests::a_peer_cannot_fill_the_mempool` | Fixed: one peer's gossip keeps at most `MAX_PENDING_PER_PEER` (1024) transactions and `MAX_PENDING_BYTES_PER_PEER` (two blocks) pending; more is dropped. A node's own transactions are not bounded. A dropped honest transaction still reaches a block through its submitter's own turns as leader. |
| BUG-11 | High: the anchor disabled for good by one writer | `AnchorStore::acknowledgments` downloaded every object under `acknowledgments/`, one after another, whole, with no deadline of its own, and any error failed the read. Every node may create objects there, and WORM keeps them: 50 000 small objects or one of 5 GB made every node start degraded (no anchored marks, no rollback detection) at every start. | `anchor::tests::acknowledgment_tests::junk_under_acknowledgments_is_left_out` | Fixed: only objects named `<generation>-<hash>` and at most `MAX_ACKNOWLEDGMENT_BYTES` (64 KiB) are read, 16 at a time, at once with the nodes' records and under `ANCHOR_NODE_TIMEOUT`. On a timeout only the node's own `--anchor-acknowledgment` counts: after an acknowledged rollback, a node without it stops (exit 77) rather than start degraded. |
| BUG-12 | High: one node takes the gateway down | The gateway read a node's answer whole (`response.bytes()`). | BUG-13 | Medium: an impostor's TLS key pinned as attested | The gateway and `mpc-admin attest` verified the statement's `evidence`, which binds `evidence.keys`, then pinned and printed `statement.keys` and wrote out `statement.tls_certificate`, without comparing the two (`check_statement` did). Someone on the path with a client certificate of `--client-ca` could relay the nonce to the real node and return its evidence next to their own TLS key. Signatures stayed safe (the gateway verifies each), but "attested" no longer meant the attested key. | E2E `gateway_1`, `gateway_3`, `tee_*` (honest nodes still attest); no forging test | Fixed: both refuse a statement whose evidence names other keys. |
| H-1 | Hardening | The task body decremented the in-flight counter, so a task that ended abnormally would leak one of the 256 slots. No reachable path was found. | none | A drop guard decrements it. |

The guarantees come from different places. Do not confuse them:

- **Cryptographic threshold.** Any 3 of 4 shares sign; 2 cannot. A share signs only what its node
  has committed.
- **Consensus BFT.** Simplex with `n = 4` tolerates `f = 1` Byzantine validator. Authorization
  safety rests on it.
- **Crash tolerance.** Atomic commits, replay from marshal, and the height-continuity check
  (BUG-2).
- **Rollback resistance.** Only what the finalized history of honest peers provides. A rolled-back
  minority re-syncs (and stays connected if its consensus journal was kept, L-7). A rolled-back
  quorum is undetected (L-1).
- **Slashing protection.** The replicated state machine decides each validator duty by the
  specification's rules over the validator's whole history. The decision is committed with the
  authorization, and every keyholder checks it. Its durability is that of the replicated state: it
  survives crashes, restarts and a minority rollback, but not a quorum rollback (L-1). The
  development API (`dev-api` builds only) has no slashing protection: its nonces are
  caller-chosen.

## 7. Reproducing

```bash
cargo test                                                   # unit + simulations
MODEL_SEEDS=2000 HOSTILE_SEEDS=500 cargo test --lib storage::tests::model  # more seeds
IT_HOME=~/eth-mpc-it ./integration/ethereum/scripts/env.sh fuzz all 3600 4  # 1 h per target
IT_HOME=~/eth-mpc-it ./integration/ethereum/scripts/env.sh validate 3       # every check, 3 E2E runs
cargo test --features test-hooks --test e2e                  # real processes
cargo test --features test-hooks --test e2e rollback::a2_whole -- --ignored   # L-1, fails
cargo test --features test-hooks --test e2e eth2::e2e_eth_l1 -- --ignored     # L-1 for duties, fails
cargo test --features test-hooks --test e2e eth2::                            # Web3Signer E2E
SIM_SEED=7 cargo test --test eth_duties                                       # another schedule
SLASHING_SEEDS=5000 cargo test --release --lib logarithmic_checks             # differential test
cargo test --release --test eth_bench -- --ignored --nocapture                # roots, slashing checks
cargo test --release --lib apply_cost -- --ignored --nocapture                # apply cost vs history
python3 -I tests/fixtures/web3signer/ssz_roots.py tests/fixtures/web3signer/*.json   # independent roots
cargo test --features test-hooks --test e2e lag:: -- --nocapture      # E2E_SEED=<seed> to replay
cargo test --release --features test-hooks --test e2e latency -- --ignored --nocapture
E2E_KEEP=1 cargo test --features test-hooks --test e2e <name>               # keep logs
```

The deterministic simulations use commonware's default seed. A failed real-process test keeps its
directory (node logs) and prints its path.
